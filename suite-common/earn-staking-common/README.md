# @suite-common/earn-staking-common

Staking contracts shared by the staking packages, the network packages and the apps: providers, product descriptors and product info, positions, plans and steps, platform support, the account data products read and the product adapter. The package depends on zod and `@trezor/*` only, so a network package can implement the adapter and the contracts can move to `@trezor` scope unchanged. `forbiddenDeps.config.ts` enforces the boundary.

## Contracts

Data contracts are Zod schemas with their TypeScript types inferred from them, so every value stored in Redux is plain, serializable data. Their objects are strict: an unknown key is rejected, not stripped. Ids this package owns, such as amounts, provider ids and product ids, use Zod's `.brand()`. A product id is `symbol:asset:provider:type`: the asset segment is the network symbol for a product that stakes the network's coin and the token symbol for one that stakes a token, whose descriptor also carries the contract, so a token staked on another network, such as POL on Ethereum, is a product of its own. Ids owned elsewhere, such as `NetworkSymbol`, are validated against their own branded types. Behavior contracts, such as the product adapter, are plain types. Descriptors are parsed when products are registered; positions and plans are checked through `assertStakingPosition` and `assertStakingPlan`, which run in development and tests only.

Adapters receive a `StakingAccount`: the backend fields of Connect's `AccountInfo` that products read (descriptor, balances, addresses, UTXOs and the network-specific `misc` data) plus the account's symbol, path and account type. The app `Account` is assignable to it as it is, so no mapping is needed, and a network package can implement the adapter against the same shape. `@suite-common/earn-staking` attaches the account key to positions and plans when it stores them.

Fee levels are the subset of the apps' precomposed levels that both fee pickers read: a partial record over Connect's fee labels whose entries are either `final` (fee, total spent, the rate as the network states it or `null` where the chain has none, an integer limit or `null`, send-max and the four `extras` the fee pickers read: bytes, the estimated limit and the EIP-1559 pair) or `error` (the compose error code and its message). A composed step carries those levels, the outputs the app review shows, the adapter-owned `unsignedTx` and `validityMs`, how long a signature stays broadcastable from the start of signing. An adapter that cannot continue throws a `StakingAdapterError` whose `code` the engine stores; it never stores the message.

`@suite-common/earn-staking-common/mocks` holds test factories.
