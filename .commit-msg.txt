feat(build): migrate publishable @trezor/* packages to tsdown

Replace the per-package tsc + Babel + sed build pipeline with tsdown
across all 22 publishable @trezor/* packages. Each package now has a
~3-line tsdown.config.ts that calls a shared factory in scripts/build/.

What tsdown replaces:
- tsc --build tsconfig.lib.json + tsc --build tsconfig.libESM.json
- scripts/publish/replace-imports.sh
- Babel plugins (sanitize-internal-imports, add-js-extension)
- Sed .d.ts rewriting + .js to .mjs renaming

What stays custom:
- scripts/inline-devdep-types.mjs for packages with @trezor/* devDep
  type leaks (connect-common, connect-web, connect-webextension,
  connect-mobile). Now falls back from libDev/ to lib/ and libESM/ so
  it works in the nx pipeline that runs ^build:lib first.
- scripts/build/post-build.mjs rewrites @trezor/X/src/Y to
  @trezor/X/lib|libESM/Y in JS and .d.ts after tsdown emits.
- Webpack worker build in blockchain-link is untouched.

Two output modes:
- bundled (createConfig({ entry: [...] })) for packages with a fixed
  public API.
- unbundle (createConfig({ unbundle: true })) for packages exposing
  wildcard subpath exports like ./lib/*.

nx.json: build:lib now dependsOn ^build:lib so dependent packages'
lib/ exists before inline-devdep-types runs.

Migrated:
- connect, connect-common, connect-web, connect-webextension,
  connect-mobile, connect-data, connect-plugin-stellar,
  connect-plugin-ethereum
- blockchain-link, blockchain-link-types, blockchain-link-utils
- utxo-lib, utils, transport, protocol, protobuf, crypto-utils,
  schema-utils, type-utils, env-utils, device-utils,
  device-authenticity, websocket-client

Removed:
- scripts/publish/ (replace-imports.sh + 4 babel files)
- Root tsconfig.lib.json, tsconfig.libESM.json
- All per-package tsconfig.lib.json and tsconfig.libESM.json
