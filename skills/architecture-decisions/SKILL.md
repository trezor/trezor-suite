# Architecture decisions

Before choosing an approach, check the ADR index below. Read each ADR in full if its scope or
reading conditions match the task. Recheck the index if the task expands to other areas.

Follow the applicable decisions and constraints, even where existing code uses older patterns. If a
task conflicts with an accepted ADR, explain the conflict and link to the decision. Use the
[ADR process](../../docs/adr/README.md) to propose a replacement when a decision needs to change. Do
not rewrite accepted decisions.

## Keep the index current

When an ADR is accepted, add its title and link, the packages or behavior it governs, and the tasks
that require reading it. Replace superseded entries with their successors. Proposed and rejected
ADRs are not binding and do not belong in this index.
